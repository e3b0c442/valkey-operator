## Architecture and Design Patterns

### Project Structure
This is a kubebuilder-based Kubernetes operator following the standard kubebuilder project layout.

### API Types (to be created)
- **Location:** `api/<version>/<kind>_types.go`
- **Tool:** Use kubebuilder CLI to scaffold (never create manually)
- **Pattern:** Kubernetes CustomResourceDefinition (CRD) pattern
- **Markers:** Use kubebuilder markers for validation and CRD generation
- **Example structure:**
  ```go
  // +kubebuilder:object:root=true
  // +kubebuilder:subresource:status
  type Valkey struct {
      metav1.TypeMeta   `json:",inline"`
      metav1.ObjectMeta `json:"metadata,omitempty"`
      Spec   ValkeySpec   `json:"spec,omitempty"`
      Status ValkeyStatus `json:"status,omitempty"`
  }
  ```

### Controllers (to be created)
- **Location:** `internal/controller/` or `controllers/` (kubebuilder determines)
- **Pattern:** Controller-runtime's Reconcile pattern
- **Registration:** Automatic via kubebuilder CLI at `// +kubebuilder:scaffold:builder` in `cmd/main.go`
- **Structure:** One controller per resource type

### Scheme Registration
- **Location:** `cmd/main.go` in the `init()` function
- **Marker:** `// +kubebuilder:scaffold:scheme`
- **Process:** Automatic when using kubebuilder CLI

### Design Principles
- **Single Responsibility:** One controller per resource type
- **Idempotency:** Reconcile functions must be idempotent
- **Error Handling:** Return errors for retry, use `ctrl.Result` for requeue logic
- **Observability:** Use structured logging throughout

## Code Style and Conventions

### File Headers
- **Required:** All Go files must include license boilerplate from `hack/boilerplate.go.txt`
- **Generated Files:** Marked with `// Code generated by tool. DO NOT EDIT.` - never edit these

### Naming Conventions
- **API Types:** PascalCase (e.g., `Valkey`, `ValkeySpec`)
- **Controllers:** PascalCase with "Reconciler" suffix (e.g., `ValkeyReconciler`)
- **Functions:** camelCase for private, PascalCase for exported
- **Constants:** PascalCase or camelCase depending on scope

### Kubebuilder Markers
**Required for code generation - use these markers:**

- `// +kubebuilder:object:root=true` - Marks root object for CRD generation
- `// +kubebuilder:subresource:status` - Enables status subresource
- `// +kubebuilder:rbac:groups=...,resources=...,verbs=...` - RBAC permissions
- `// +kubebuilder:scaffold:...` - Scaffold markers (DO NOT REMOVE)
- `// +kubebuilder:validation:...` - Validation rules for fields

### Logging Standards
- **Use:** `ctrl.Log` or `ctrl.Log.WithName("controller-name")`
- **Format:** Structured logging with key-value pairs
- **Example:** `log.Info("reconciling resource", "valkey", req.NamespacedName, "phase", phase)`
- **Levels:** Use appropriate levels (Info, Error, Debug, V(1-10))

### Error Handling Patterns
- **Reconcile Errors:** Return errors for automatic retry
- **Immediate Retry:** `ctrl.Result{Requeue: true}`
- **Delayed Retry:** `ctrl.Result{RequeueAfter: time.Duration}`
- **No Retry:** `ctrl.Result{}` (success)
- **Always log errors** before returning them

## Common Tasks

### Adding a New API Type (TDD Workflow)

**CRITICAL: Use kubebuilder CLI and follow TDD**

1. **Write tests first** (unit and e2e) describing desired API behavior
   - Test API type validation, field constraints, and CRD generation
   - Test DeepCopy methods work correctly
   - Test OpenAPI schema generation
2. **Scaffold API** using kubebuilder:
   ```bash
   kubebuilder create api --group <group> --version <version> --kind <Kind>
   ```
   Note: Answer "no" to creating controller if you only want the API type
3. **Edit API types** in generated `api/<version>/<kind>_types.go`
   - Add kubebuilder markers for validation and CRD generation
   - Define Spec and Status structs
   - Add field validation markers (e.g., `// +kubebuilder:validation:Required`)
4. **Run `make manifests`** to generate CRDs
5. **Run `make generate`** to generate DeepCopy methods
6. **Verify tests pass** - API type validation, CRD generation, and DeepCopy methods
7. **Update documentation** (AGENTS.md, README.md, API docs)

### Adding a New Controller (TDD Workflow)

**CRITICAL: Use kubebuilder CLI and follow TDD**

1. **Write tests first** (unit and e2e) describing desired controller behavior
2. **Scaffold controller** using kubebuilder:
   ```bash
   kubebuilder create controller --group <group> --version <version> --kind <Kind>
   ```
   Or if API already exists:
   ```bash
   kubebuilder create api --group <group> --version <version> --kind <Kind> --controller --resource
   ```
3. **Edit controller** in generated location (`internal/controller/` or `controllers/`)
   - Implement `Reconcile` method
   - Add RBAC markers for required permissions
4. **Run `make manifests`** to update RBAC
5. **Implement logic** to make tests pass
6. **Update documentation** (AGENTS.md, README.md, controller docs)

### Updating Dependencies
1. Edit `go.mod`
2. Run `go mod tidy`
3. Run `go mod vendor` (if using vendoring)
4. Test with `make test`

### Building and Deploying
1. Build image: `make docker-build IMG=<registry>/valkey-operator:<tag>`
2. Push image: `make docker-push IMG=<registry>/valkey-operator:<tag>`
3. Install CRDs: `make install`
4. Deploy operator: `make deploy IMG=<registry>/valkey-operator:<tag>`

## Troubleshooting

### CRDs Not Appearing
- Run `make manifests` to regenerate
- Check `config/crd/bases/` for generated files

### Build Failures
- Ensure Go version matches (1.24.6+)
- Run `go mod tidy` to fix dependencies
- Check for missing tools: `make controller-gen kustomize`

- Ensure envtest binaries are set up: `make setup-envtest`
- Check Kubernetes version compatibility
- Verify test cluster access for e2e tests

### Deployment Issues
- Check RBAC permissions
- Verify image pull permissions
- Check manager logs: `kubectl logs -n valkey-operator-system deployment/valkey-operator-controller-manager`
